How a shift works

One ticket, start to finish.

A ticket is the unit of this app. A colleague asks for a result. You write the T-SQL in a window that looks like SSMS. We mark it the way they would — not four multiple-choice options. If it’s right, the next one lands.

What a ticket is worth. At work it is the inbox item: last week’s orders by ten, returns that don’t match, a JOIN that doubled the total. Here it is the same thing — one request, one query, a mark. Five minutes. The value is you type every time, until the habit is there. Monday’s shift is free.

  • One company. Harbour & Co: customers, orders, order lines, products, returns, staff. Messy, like real tables.
  • Strict marking. SELECT * doesn’t pass. Extra columns, the wrong headers or a missing ORDER BY get sent back.
  • Real SQL Server habits. TOP, ISNULL, GETDATE, square brackets, F5 to execute, errors worded like SSMS.
A working week, not a syllabus

Monday is free. The rest of the week is the real inbox.

Seven working days of about six tickets each. A walkthrough the first time you meet CASE, LEFT JOIN or a CTE, then two reps on your own. Five minutes a ticket is a month of days.
